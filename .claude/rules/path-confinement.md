# 外部由来の識別子・論理パスをファイルパス化する処理は封じ込め必須

PR番号・論理パス（`/tmp/...`）等、呼び出し元から渡される値をもとにファイルシステムパスを構築する処理は、`path.resolve`/`path.join`が`../`を正規化してしまうため、検証なしでは意図したディレクトリ外への読み書き（path traversal）を許してしまう。

- `scripts/shared/review-manager-paths.js`（PR #84）・`scripts/write-draft.js`（PR #85）で同種のロジックが独立に実装され、後者は前者を参考にしても共有化されなかった。
- 対策: 外部由来の値からパスを構築する場合は、`scripts/shared/safe-path.js`の`assertWithinRoot(allowedRoot, candidate)`（またはそれに相当する「解決後パスが許可ルート配下に収まることを確認する」共有ヘルパー）を使う。生の`path.join`/テンプレートリテラルで直接組み立てて済ませない。
- 識別子自体の形式検証（例: PR番号が正整数か）は各スクリプト固有の前処理として残してよいが、封じ込めチェック（許可ルート配下確認）は共有ヘルパーに一本化する。
