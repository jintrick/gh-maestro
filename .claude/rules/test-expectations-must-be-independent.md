# 期待値を検証対象から導出しない

テストの期待値を、検証対象そのものから導出してはならない。それは自己整合性の確認でしかなく、対象が丸ごと欠落しても通る。

期待値は検証対象と独立した出所から取る。

- 対象自身が持つ構造宣言（例: 文書冒頭の `<!-- gh-maestro-structure: stages=13 -->`）
- 別ファイルの定数・スキーマ
- 外部仕様

実障害: PR #420 で `tests/orchestrator-step-numbering.test.js` を「期待値の焼き込みをやめる」方針で書き換えた際、文書から検出できた項目だけを集めて整合性を検証する形にしたため、工程1の中項目を全削除しても、工程3以降を丸ごと削除しても通る状態になった（Review Manager 指摘、Issue #419）。

検証を緩める修正では、緩めた結果として検出できなくなるケースを1つ挙げ、それが依然として検出されることを実測で示すこと。
