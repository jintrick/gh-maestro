# 外部コマンド依存の安全ガードはフェイルクローズにする

安全ガード（危険な操作を止めるためのチェック）が、外部コマンド（`git` 等）の実行結果に依存している場合、その検出自体が失敗した（コマンドが無い、例外を投げた等）ときは、警告して処理を継続するのではなく、`--force` 等の明示的なフラグなしでは中断する。

検出失敗は「安全と判定できない」ことを意味する。安全と確認できない場合は安全側（中断）に倒す。

# フェイルクローズのテストは、危険な操作が実行されないことを検証する

エラーが報告されることの確認で終わらせない。プロセスを起動しない・書き込まない・次段へ進まない、という不作為そのものを検証する。

また、テストに注入した値だけで検証しない。注入した値で通ることは、本番の既定経路が通ることを意味しない。

# ガードの名前は、実際に保証している範囲と一致させる

安全ガードやその周辺の変数・関数・ログ文言に、実際には提供していない保証を含意する名前を付けない。名前が含意する範囲と、コードが実際に守っている範囲を一致させる。

「保護」「検証」「安全」等の語を使う前に、守る対象と守らない対象を言語化する。守らない範囲があるなら名前をその範囲に合わせて狭める。ログ・エラー文言も同様に扱う。読み手は名前から危険度を推定するため、過大な名前は過大な対応を誘発する。
