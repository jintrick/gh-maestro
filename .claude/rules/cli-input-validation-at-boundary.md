# CLIの入力検証はCLI境界で検証する

CLIスクリプトの引数検証（必須・排他・値の妥当性）を追加または変更したときは、検証ヘルパーの単体呼び出しだけで済ませず、`spawnSync(process.execPath, [SCRIPT, ...args])` でCLIを子プロセス起動し、非ゼロ終了とエラーメッセージを検証するテストを残す。

ヘルパー単体のテストだけでは、引数解析からヘルパーへの結線が外れてもテストが緑のままになる。PR #488 では `--title-only` と `--body-file` の排他条件が `validateBodyMode()` の直接呼び出しでのみ検証されており、`parseFlags()` の結果をヘルパーへ渡すエントリポイントの結線・非ゼロ終了・`gh` やassistantを呼ばずに終了することは検証されていなかった。

入力検証の失敗はworkspace解決やGitHub呼び出しより前に起きるため、子プロセス起動しても外部副作用を伴わない。
