# 子プロセス境界のargvを注入モックで飛ばしたままにしない

兄弟CLIを`spawnSync`等で呼ぶ関数を、テストが常に依存注入で差し替えていると、実際に渡しているargvは一度も検証されない。呼ばれる側のCLIが引数規約を変えても、呼ぶ側が旧規約のままでも、両者のテストは緑のまま通る。

- 実障害（PR #330 Review Manager指摘）: `remove-worker.js`のワーカー名指定を`--worker-name`から位置引数へ変更した際、`finalize-issue.js`の`defaultRemoveWorker()`が組み立てるargvを検証するテストが存在しなかった。`tests/finalize-issue.test.js`は全ケースで`removeWorkerFn`を注入しており、呼び出しが旧形式に戻っても全テストが緑のままになる状態だった。

注入自体は禁止しない（実プロセス起動の抑制には必要）。ただし、argvを組み立てて子プロセスを起動する関数については、注入を省略して実物を通し、argvと呼ばれる側の受理を一緒に固定するケースを最低1本持つこと。副作用のないフィクスチャ（PID・worktreeを持たないregistryエントリ等）を使えば実プロセスを起動せずに固定できる。

外部プロセスを注入モックで差し替えるテストは、モックが受け取った引数を捕捉し、契約上必須のフラグ・フィールドが含まれることをアサートする。応答のfixtureだけを返して引数を検証しないモックにしない。

## 実プロセスの起動は、プロセス境界そのものが検証対象のときだけ

上の規約は「argvを一度も通さないまま注入で済ませるな」と言っている。その裏返しとして、**プロセス境界と関係のない検証に実プロセスを使ってはならない。** 1件ずつは正しく見えても、ケース数を掛けた瞬間にテストスイート全体を支配する。

- **分岐の網羅は純粋関数を直接呼ぶ。** 引数バリデーションのような文字列判定を、分岐ごとにCLIプロセスを起動して検証しない。argvと終了コードの契約を固定する代表ケースを1本だけ実プロセスで通し、残りの分岐は検証関数を直接呼ぶ。検証ロジックがCLI本体に埋まっていて直接呼べない場合は、純粋関数として切り出してから書く。
- **本番コードが外部プロセスを呼ぶ箇所には、その呼び出し元自身に注入点を置く。** 呼び出し先の共有モジュールに`_setXxx`があっても、呼び出し元のスクリプトに無ければテストからは差し替えられない。共有モジュール側をモックして「差し替えたつもり」になっている状態を疑う。
- **重いフィクスチャはケースごとに作り直さない。** 全ケースで同一のgitリポジトリやディレクトリ構造は、一度だけ構築してコピーで配る。
- **実時間を待たない。** タイムアウト・リトライ・ポーリング間隔は注入で潰す。テストの実行時間が待機時間に比例している状態を作らない。

ただし、これらで速くするときに**置き換え前が保証していた内容を落としてはならない**。速くなり件数も変わらないのに保証だけが減っている状態を作らない。

- 実障害（Issue #390）: `npm test`全体100.9秒に対し、上位6ファイルが個別実行235秒中の175秒を占めていた。`spawn-worker.test.js`は引数バリデーション約60分岐すべてをNode子プロセス起動で検証して22秒。`msg-poll.js` / `worker-supervisor.js`は`main()`内の`getProcessStartTime`がWindowsでPowerShellを同期起動し、221ケース分積まれて113秒。`gh-maestro-setup.test.js`はケースごとに実gitリポジトリを構築して12秒。`assistant-watch.test.js`は`--wait`を実時間で待って13秒。下位99ファイルは合計10秒未満であり、時間は一点に集中していた。
- 同PRでは高速化と引き換えに保証を落とす回帰も出た。`checkAgentExists`の肯定系を`_setSpawnSync(() => ({ status: 0 }))`に置き換えて`bash -lc command -v 'node'`の契約検証が消え、`_setGetProcessStartTime(() => null)`をモジュール全体に固定して`main()`が取得した起動時刻が`createDeadManSwitch`へ渡ることの検証が消えた。いずれもモックが受け取った引数を記録してアサートする形で回復させた。
