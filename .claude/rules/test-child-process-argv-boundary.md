# 子プロセス境界のargvを注入モックで飛ばしたままにしない

兄弟CLIを`spawnSync`等で呼ぶ関数を、テストが常に依存注入で差し替えていると、実際に渡しているargvは一度も検証されない。呼ばれる側のCLIが引数規約を変えても、呼ぶ側が旧規約のままでも、両者のテストは緑のまま通る。

- 実障害（PR #330 Review Manager指摘）: `remove-worker.js`のワーカー名指定を`--worker-name`から位置引数へ変更した際、`finalize-issue.js`の`defaultRemoveWorker()`が組み立てるargvを検証するテストが存在しなかった。`tests/finalize-issue.test.js`は全ケースで`removeWorkerFn`を注入しており、呼び出しが旧形式に戻っても全テストが緑のままになる状態だった。

注入自体は禁止しない（実プロセス起動の抑制には必要）。ただし、argvを組み立てて子プロセスを起動する関数については、注入を省略して実物を通し、argvと呼ばれる側の受理を一緒に固定するケースを最低1本持つこと。副作用のないフィクスチャ（PID・worktreeを持たないregistryエントリ等）を使えば実プロセスを起動せずに固定できる。
