# 本番常駐プロセスの強制置換主体をallowlistで限定する

## 決めたこと

本番で稼働する常駐プロセスを強制置換できる実行主体をallowlistで限定する。ワーカーの実行経路にはその権限を与えず、置換機能は一時ワークスペースで検証する（Issue #384・#385）。

## なぜ

常駐プロセスは指示配送と監視の土台であり、ワーカーがテスト目的で置換すると、ワーカーへの指示が届かなくなりシステム全体が止まる。強制置換が必要なのは人間とorchestratorの運用経路だけである。実行主体を明示的に限定し、一時ワークスペースで試験すれば、本番のプロセスを誤って操作する権限と検証対象を分離できる。

## 却下した案

- 呼び出し側が指定した強制フラグだけで本番置換を許可する案。ワーカーも同じ経路を呼べてしまい、権限境界にならないため採らなかった。
- すべての実行主体から強制置換を取り上げる案。人間とorchestratorが必要な更新を行えなくなるため採らなかった。
- 本番ワークスペースでのみ置換を検証する案。検証そのものが稼働中の配送を止める危険を持つため採らなかった。
