# ヘッドレスのエージェント作業を自動再試行しない

## 決めたこと

ヘッドレスワーカーが失敗した場合、その失敗を一度 orchestrator に返す。再試行、再起動、人間へのエスカレーション、放棄は orchestrator が決める。モデル自身の再試行を含め、エージェント作業を繰り返すループをヘッドレスプロセスへ導入しない。ただし、単一の一時的なファイル操作やHTTP要求に対する、回数または期限を決めた機械的な再試行は対象外とする。

## なぜ

ヘッドレスプロセスの暴走は画面から見えない。orchestrator は報告が遅れているだけだと解釈して待ち続け、人間にも異常が届かないままモデルがクォータを消費し続ける。失敗を一度返せば、再試行するかどうかを可視化された判断に戻せる。単一のI/Oだけを決定論的に再試行する余地を残すことで、エージェント作業のループと一時的な通信障害への対処を区別できる。

## 却下した案

- ヘッドレスワーカー自身が成功するまで `while` ループで作業をやり直す案。異常が見えず、終了条件をモデルの裁量に置くため採らなかった。
- 失敗時にワーカーを自動再起動して収束を待つ案。再試行の判断とクォータ消費が可視化されないまま増えるため採らなかった。
- 一時的なI/Oの失敗も一切再試行しない案。限定的で決定論的なI/O再試行まで禁止する必要はないため採らなかった。
