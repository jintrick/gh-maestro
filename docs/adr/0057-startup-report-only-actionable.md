# 起動時の報告は、作業開始に役立つことと動作に悪影響があることだけにする

## 決めたこと

/gh-maestro の起動時に orchestrator が人間へ伝えるのは、人間がこれから作業を始めるのに役立つこと（直近の Issue/PR の動きなど）と、gh-maestro の動作に悪影響があることだけにする。検査が問題なく済んだこと、正常であること、宣言済みであること、動作に影響しない旧形式の記録が残っていることは伝えない。起動時の検査を新しく足すときも、その検査の正常な結果は伝えない。

## なぜ

起動時の検査は増え続けており、そのたびに「回収対象なし」「宣言済み」「壊れていない」のような結果が報告に積み上がっていた。人間はそれを読んでも何もすることがなく、役に立たない情報を読む手間とトークンの無駄になる。必要な事柄（対応が要る異常）も、正常の報告に埋もれて目に入りにくくなる。伝えるかどうかを検査ごとの決め事ではなく一つの基準で決めることで、検査を足しても報告が膨らまない（#730）。

## 却下した案

- 検査結果をすべて人間へ報告する案。変更前の `skills/gh-maestro/SKILL.md` は、旧形式の遺物が `present` / `unknown` / `incomplete` なら一律に人間へ提示し、sweep の回収結果も表示する作りだった。正常でも伝えれば何が確認されたかが見える、という透明性の利点はあるが、人間が何も判断しない情報を毎回読ませることになるので採らなかった。
- 旧形式の遺物のうち、今のコードで動作が「変わる」もの（12項目）をすべて伝える案。install やワーカー停止の互換処理が片付けるだけの項目まで含まれ、人間がすることは無いので、悪影響が出る8項目に絞った。
