# 堅牢性を速度より優先する

## 決めたこと

gh-maestro は AI エージェント開発の基盤である。実装の速さや手軽さより、壊れにくさを優先する。構造的な脆弱性を見つけたら、その場で握り潰さず記録して起票を相談する。

## なぜ

このシステムの上で他のプロジェクトの開発が回る。基盤が壊れると、その上の作業がすべて止まる。しかもヘッドレスで動くワーカーの障害は誰の目にも触れないため、壊れたことに気づくまでの時間が長い。手戻りの単位がセッション単位・Issue単位になる。

## 却下した案

手早く動くものを先に作り、問題が出てから直す案。ヘッドレス実行では問題が表面化しないまま quota を消費し続けるため、「出てから直す」が成立しない。
