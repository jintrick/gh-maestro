# 規約同期の失敗を記録しcommitを止めない

## 決めたこと

規約同期が失敗してもcommitは成立させ、共有ヘルパーで失敗の種類、時刻、エラー、対象commitなどを `sync-failures/` に記録する。次のセッション開始時にその記録を確認する。`.claude/rules/` を同期する `sync-rules.js` と `scripts/shared/sync-failure.js` の経路を維持する（Issue #393・#394）。

## なぜ

同期失敗を画面上の警告だけにすると、同期元だけが更新され、次にどの規約が古いか分からなくなる。記録を残せば、commitを止めずに失敗を永続化し、次のセッションで検出して人間とorchestratorが対処できる。同期失敗のたびにcommitを拒否すると、規約同期とは無関係の作業まで完了できず、停止の判断をフックへ渡してしまう。

## 却下した案

- 同期に失敗したらフックでcommitを拒否する案。同期以外の変更を完了できず、停止の判断を機械へ移すため採らなかった。
- 端末へ警告を表示するだけで記録を残さない案。次のセッションで失敗を検出できず、古い規約が残るため採らなかった。
- `.claude/rules/` の同期失敗記録を削除する案。共有された失敗検出経路を失い、Issue #393・#394で解決した問題を再発させるため採らなかった。
