# commit・push・mergeを自動チェックで止めない

## 決めたこと

pre-commit と pre-push でテストを走らせず、CIの通過やブランチ保護を commit・push・merge の機械的な必須条件にしない。停止の判断は orchestrator と人間が行い、機械はテスト結果と対象のcommitなどの事実を申告・公開する。結果がない、古い、または失敗している場合も自動的に再実行して塞がず、判断材料として提示する。

## なぜ

フックやCIはコーダーのセッションと異なる環境変数で動くため、コーダーのworktreeでは成功したテストが別の環境だけで失敗することがある。再現できない失敗を直すよう求められたコーダーには収束先がなく、実際に70分を費やした。pushを塞ぐとコーダーは完了・報告できず、mergeを塞ぐと緊急修正まで拒否される。さらに、pre-pushの環境変数がテストから実リポジトリへ漏れた事故もある（Issue #283）。テスト結果を申告して対象commitへ結び付け、人間と orchestrator が確認する形なら、環境差による自動停止と再実行を避けられる。

## 却下した案

- pre-commit または pre-push でテストを実行し、失敗時にcommitやpushを拒否する案。実行環境の差で再現しない失敗を生み、コーダーを完了不能にするため採らなかった。
- CIの成功やブランチ保護をmergeの必須条件にする案。緊急修正まで機械的に拒否し、停止の判断を機構へ移すため採らなかった。
- 失敗したテストを機械が自動再実行し、成功するまで公開を止める案。環境差を増やし、事実の報告ではなく機械的な判断になるため採らなかった。
