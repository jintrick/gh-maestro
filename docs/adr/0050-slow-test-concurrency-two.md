# slow 層の並列数は CPU 数から決めず、2に固定する

## 決めたこと

slow 層のテストは、並列数を2に固定して実行する。CPU 数から並列数を決める方式（`dynamicConcurrency`）は使わない。

## なぜ

2026-10-30、Issue #662 / PR #663 の slow 実行は、CPU 数から決まった並列数11で走り、`tests/slow/msg-poll.test.js` だけが12分以上終わらなかった。同じテストを1件ずつ単独で実行すると、全259件が20秒以内に終わり、止まるものは無かった。止まった原因は特定できていない。

slow 層のテストは実プロセス・git・PowerShell を起動するものばかりで、同時に動く数が多いほどテスト同士が干渉する機会が増える。一方、`config status` の廃止後の slow 層は単独実測の合計で約160秒であり、2並列でも1分半前後で終わる見込みで、全体を最悪3〜5分で終えるという要求に十分収まる。速さを少し捨てて、安定を優先した。

## 却下した案

- CPU 数から並列数を決める方式（このマシンでは11並列）。今回止まった構成そのものであり、原因が分からないまま干渉の機会を最大にするため採らなかった。
- 3並列。2並列との差は約30秒しかなく、その差のために同時に動くプロセスを増やす理由が無いため採らなかった。
- 直列（並列数1）。約2分40秒で上限には収まるが、2並列で干渉の機会をほとんど増やさずに時間を半分近くにできるため採らなかった。
