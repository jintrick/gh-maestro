# 型チェックは npm スクリプト typecheck で呼び、テスト層だけを config.json で宣言する

## 決めたこと

push 時に申告する型チェックは、lint と同じく対象リポジトリの package.json にある npm スクリプト `typecheck` を共有runnerが呼び、テスト・lint と同じ成果物に記録して申告する。`.gh-maestro/config.json` に型チェックのコマンドを宣言する形は採らない。テスト層は従来どおり `.gh-maestro/config.json` で宣言する。`typecheck` スクリプトが無い場合は黙ってスキップせず「未定義」として記録・申告する（Issue #594、PR #595）。

## なぜ

lint は既に npm スクリプト `lint` を呼ぶ形で、どの linter を使うかは各リポジトリのスクリプトの中身で決まっている。型チェックも同じ入口にすれば、package.json という各リポジトリが必ず書く場所で検査の中身を決められ、gh-maestro 側に型チェッカーの種類を持ち込まずに済む。一方テスト層は、scope・既定のテストファイル・変更ファイルからテストを引く mapping を持ち、package.json のスクリプトには置き場所がない。さらにこのリポジトリでは `npm test` 自体がテスト層を実行する入口であり、テスト層を npm スクリプトで定義させると入口と中身が循環する。スクリプトが無いことを黙ってスキップしないのは、撤去前の pre-push checks フックが検出対象の不在を黙ってスキップし、抜け道になっていたため（c5a3d89、撤去は eaa6e38）。

この判断は、gh-maestro が型チェックを申告できる対象を npm プロジェクトに限ることを受け入れている。

## 却下した案

- 型チェックのコマンドを `.gh-maestro/config.json` に名前付きで宣言させる案。人間が最初に提案した形で、npm を使わないリポジトリでも使え、テスト層の宣言と置き場所が揃う。しかし lint が npm スクリプトで呼ばれている現状と入口が分かれ、検査ごとに宣言の場所が異なる不揃いを生むため採らなかった。
- テストも npm スクリプトへ寄せる案。テスト層が持つ scope・mapping 等の置き場所が package.json に無く、`npm test` との循環も生じるため採らなかった。
- package.json のスクリプト名から検査を自動検出し、無ければスキップする案（撤去前の checks フックの方式）。不在が誰にも見えない抜け道になったため採らなかった。
