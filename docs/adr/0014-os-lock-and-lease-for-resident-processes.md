# 常駐プロセスの重複起動をOSロックとリースで防ぐ

## 決めたこと

常駐プロセスの重複起動防止には、OSが提供するロックまたはリースを使う。取得前にプロセス登録簿の文字列だけで重複を判定せず、workspaceを正規化した識別と、取得失敗時に安全側へ倒れる扱いを組み合わせる（Issue #240・#241）。

## なぜ

workspaceの大文字小文字や末尾の区切り文字が異なると、文字列比較だけの登録簿検査を同じ場所として扱えない。複数プロセスが同時に検査してから起動する競合も、登録簿を読むだけでは防げない。OSロックまたはリースを起動の排他条件にすれば、表記差と検査・起動間の競合を別々の経路で作り込まずに扱える。

## 却下した案

- 登録簿を読み、workspace文字列を比較してから起動するだけの案。表記差と同時起動の競合を防げないため採らなかった。
- 強制起動オプションでロック取得を迂回する案。重複起動を防ぐ契約そのものを呼び出し側の指定で無効にするため採らなかった。
- プロセスが生きているか不明なときに起動を許可する案。排他を確実に確認できない状態で二重起動を招くため採らなかった。
