# 計画用の上位モデルは、同じエージェント定義の中に planExtraArgs で書く

## 決めたこと

coder・senior-coder が計画の間だけ使う上位モデルは、config.json の `agents` の各エージェント定義に `planExtraArgs` として書く。計画が承認されるまでは `extraArgs` の代わりに `planExtraArgs` を使い、承認後は `extraArgs` に戻して同じ会話を再開する。`planExtraArgs` が無い定義は今までどおり動く（Issue #725）。

## なぜ

計画から実装へ切り替えても、ワーカーは同じ会話を引き継いで再開する。会話の記録は CLI ごとのものなので、上位と下位は必ず同じ CLI でなければならない。上位モデルを同じエージェント定義の中に書けば、`extends` が1つなので、同じ CLI であることが設定の形で保証され、「上位と下位で CLI が違う」という誤設定がそもそも書けない。config.json は人間が直接編集する箇所であり、上位と下位が1か所に並んでいるほうが読み書きしやすい。

## 却下した案

- `skillAgentMap` と並べて `skillPlanAgentMap` を新設し、スキルごとに計画用のエージェント名を指す案。orchestrator が最初に出した案で、既存の `skillAgentMap` と同じ形に揃う利点がある。しかし計画用と実装用が別々のエージェント定義になり、別の CLI を指す誤設定を書けてしまうため、検査が要る。人間がこの点を指摘して採らなかった。
- `skillAgentMap` の値を文字列からオブジェクトに変え、上位と下位を1か所に書く案。既存の値の型が変わり、既存の config.json をそのまま動かすという後方互換の指示に反するため採らなかった。
