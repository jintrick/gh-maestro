# 監視ペインの記録が消滅した WezTerm を指すときは、現在の WezTerm へ自動で作り直す

## 決めたこと

監視ペインの記録（`status-pane.json`）が指す WezTerm の接続先が恒久的に消滅していると判定でき、かつ呼び出し元の現在の接続先と分割元ペインが有効だと確認できる場合に限り、監視ペインを現在の WezTerm へ自動で作り直す。人間の復旧操作を待たない。消滅と判定できない照会失敗・一時的な失敗では、従来どおり作成せず記録を保持して停止する。

消滅した接続先を指す記録は、ADR 0036 のいう破損した状態ファイルではない。記録の中身は正しく、外部の実体が無くなっただけである。

## なぜ

Issue #549 / PR #550 は、別ウィンドウへ無関係な監視ペインを作る事故を防ぐため、記録された接続先を照会できないときは作成せず停止するようにした。この停止には終わりがなく、WezTerm を再起動すると古い接続先が消え、以後どのワーカー起動でも監視ペインが作られなくなった（Issue #569、voiceslide で発生）。自動の存在保証は失敗を呼び出し元へ伝えないため、人間は監視ペインが出ないことにしか気付けない。

接続先が消滅していれば、守るべき既存の監視ペインも、そのペインがあったウィンドウも存在しない。#549 が防ごうとした「存在するペインを見失って別の場所に作る」状況には当たらない。呼び出し元の現在の分割元ペインはorchestrator自身のペインであり、作り直し先として正しい。

## 却下した案

自動では作り直さず、失敗を表示して人間が復旧コマンドを実行したときだけ作り直す案。Issue #569 で orchestrator が提示し、人間が採らなかった。AGENTS.md の「安全ガードはフェイルクローズにする」と ADR 0036 の「状態ファイルを自動修復しない」に沿うため、規範だけを読む変更者には自然な選択に見える。採らなかったのは、監視ペインが必要になるのはワーカーを起動した直後であり、そこで人間の操作を要求すると、WezTerm を再起動するたびに監視が途切れることになるからである。消滅の判定を確実にできる限り、自動で作り直しても #549 の事故は起きない。
