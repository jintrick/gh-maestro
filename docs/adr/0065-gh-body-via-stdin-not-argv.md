# gh へ本文を渡すときは引数ではなく標準入力かファイルで渡す

## 決めたこと

`gh` へ Issue・PR・コメント・レビューの本文を渡すときは、引数（`-f body=…`、`--body <本文>`）で渡さない。標準入力（`-F body=@-`、`--body-file -`）かファイル（`--body-file <path>`、`--input <file>`）で渡す。共有ヘルパー（`scripts/shared/gh-comments.js`）に該当するものがあればそれを使う。

## なぜ

Windows ではコマンドの引数の長さに約32KBの上限がある。本文を引数で渡すと、本文が長くなったときに Windows でだけ投稿が ENAMETOOLONG で失敗し、短い本文のテストでは見つからない。実際に、テスト215件分の申告の表（約98KB）が Windows から投稿できず、coder が WSL から実行する回り道をした結果、node_modules への参照の混入による追加の push と、全体テストのやり直しが起きた（Issue #774）。調べると、申告・計画・レビュー・不完全レビューの通知など6スクリプトが同じ渡し方をしていた（PR #775 で修正）。

## 却下した案

- 本文を引数で渡す: 最も短く書け、`gh` の使用例にもよく現れる形だが、上の理由で採らない。
- WSL から実行して引数の上限を避ける: Issue #774 の発端となった回り道であり、node_modules の混入とテスト結果の不可視という別の問題を生んだため採らない。
- 本文を引数で渡すコードを検出するテストで禁止する（#774 の反省会で検討）: テストが失敗したとき、コーダーは例外一覧や検出規則を書き換えて通せるため、禁止の強制にならない。規範とこの記録に留めた。
