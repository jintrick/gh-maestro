# 判断と限定実行にモデル資源を分ける

## 決めたこと

要件、設計上のトレードオフ、レビュー結果のトリアージ、人間との協働には高価なモデルと人間の判断を使う。範囲が限定された実装、検索量の多い調査、ログの読解、機械的なレビューには安価または高速なワーカーを使う。ワーカーは製品判断、優先順位、マージ判断を持たず、事実・コード・構造化された指摘を返す。承認、却下、優先順位、最終的なマージ判断は orchestrator と人間が担う。

## なぜ

判断の難しさと実行作業の量は一致しない。判断を必要とする場面に資源を集中し、境界の明確な作業をワーカーへ分担すれば、限られたモデル資源を使いながら、判断の責任の所在も保てる。ワーカーに製品やマージの権限を持たせると、個別の実行結果がプロジェクトの方針を勝手に変えるため、orchestrator と人間による確認が機能しなくなる。

## 却下した案

- すべての工程を同じ高価なモデルに任せる案。単純な実行にも判断用の資源を消費し、判断と作業の責務も分離できないため採らなかった。
- ワーカーに要件の採否やマージ可否まで委ねる案。限定された作業の結果から製品上の判断を自動的に導くことになり、承認者を不明確にするため採らなかった。
