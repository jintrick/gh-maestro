# ワーカーとReview Managerの起動・ライフサイクルを共有する

## 決めたこと

ワーカー名の決定、重複起動防止、worktree作成、ヘッドレス起動、ログ配置、生存確認などの起動・ライフサイクル処理は共通の機構で扱う。Review Managerもこの機構を拡張して使い、役割ごとに独立した起動経路を増やさない（Issue #174・#191、PR #175・#192）。

## なぜ

coderとReview Managerの起動処理が別々に実装されると、重複起動防止や終了検知の修正が片方にしか届かず、同じライフサイクルの意味もずれる。共通機構を使えば、役割を増やしても起動・終了・監視の契約を一つに保てる。Review Managerを短命の特別処理として扱わず、必要な計画レビューを同じ運用基盤へ組み込める。

## 却下した案

- coderとReview Managerにそれぞれ専用の起動・終了処理を持たせる案。同じ不具合の修正と検証が二重になり、経路間の差を生むため採らなかった。
- Review Managerだけを既存のライフサイクル外で起動する案。重複起動、ログ、生存確認の責務が分散するため採らなかった。
