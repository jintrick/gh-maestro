# 作業中ワーカーへの送信ガードは、報告状況を判定できないとき送信を通す

## 決めたこと

`scripts/msg-send.js` の送信ガード（作業中で未報告のワーカーへの追加指示を、投稿前に拒否するもの）は、ワーカーが報告済みかを GitHub から判定できないときに、送信を止めずに通す。判定できないときとは、Issue のコメント一覧の取得に失敗したとき、応答を解釈できなかったとき、判定結果が不明になったときである。これは、AGENTS.md「安全ガードはフェイルクローズにする」の例外である。

一方、手元の記録（workers.json）を読めないときと、ワーカーの生死を判定できないときは、これまでどおり止める。例外は、GitHub から報告状況を読む部分だけに限る。

## なぜ

このガードが守っているのは、作業中のワーカーに追加の指示が割り込むことである。ところが、通ってしまっても、指示は Issue に投稿されるだけで、ワーカーへの配送は worker-supervisor がワーカーの作業の終了を待ってから行う。割り込みは起きず、実害は小さい。

逆に止める作りにすると、GitHub が不調な間は、orchestrator からワーカーへの指示が一切送れなくなる。しかも送信そのものも GitHub を使う。報告状況を読めないほど不調なら、送信もたいてい失敗する。止めても、増える安全はほとんど無い。

この判断は PR #264（Issue #263）で行われたが、ADR が無かった。そのうえコードのコメントは、その後削除されたルールファイル（`.claude/rules/fail-closed-safety-guards.md`）を根拠に挙げていた。そのため Issue #678 のテストの見直しで「規範違反の不具合」と判定され、Issue #680 で直し方を検討するところまで進んだ。この ADR は、その再検討を繰り返さないために書く。

## 却下した案

- AGENTS.md の規範どおり、判定できないときは止める（Issue #680 で検討した）。規範の文面には合うが、上のとおり安全はほとんど増えず、GitHub が不調な間の送信をすべて止める代償だけが残るため、採らなかった。
