# 常駐プロセス内部の通知を監査経路へ送る

## 決めたこと

常駐プロセス内部のエラーや状態通知は、ワーカーとorchestratorの運営用であるGitHub Issueコメントへ送らず、監査用の経路へ送る。常駐プロセスの居座り検知には、報告直後の正常な終了処理を許容する猶予期間を設ける（Issue #386・#387）。

## なぜ

Issueコメントは指示と報告を追跡するための通信面であり、内部監視の通知を混ぜると運営記録が無関係な情報で膨らむ。内部通知を監査経路へ分ければ、運営上のメッセージと実行基盤の診断を別々に確認できる。報告直後に猶予なく居座り警告を出すと、終了処理中の正常なプロセスを異常として扱うため、検出に時間的な余裕を持たせる。

## 却下した案

- 常駐プロセスの内部通知を`msg-send.js`経由でIssueコメントへ投稿する案。運営用の履歴と内部診断が混在するため採らなかった。
- 報告を受けた直後に猶予なく居座り警告を出す案。正常な終了処理を誤検知するため採らなかった。
- 内部通知を捨てて異常を記録しない案。運用上の原因追跡に必要な監査情報が失われるため採らなかった。
