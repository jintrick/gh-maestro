# orchestrator が承認推奨と評価した計画は、人間に問わず実装を開始する

## 決めたこと

工程5で orchestrator がコーダーの計画を「承認推奨」と評価したら、人間に提示も質問もせず、工程6で実装開始を指示する。初回の計画か修正版か、前回の差し戻しを誰が決めたかで区別しない。人間に問うのは、範囲など人間の判断を要する論点が残っているときと、architect に計画レビューを依頼するか決めるとき（工程5-[2/3]）だけである。計画の承認は orchestrator が持つ。

## なぜ

人間の要望である（#733 の計画承認時、保留 Issue #14 に記録）。orchestrator が承認推奨と評価した計画について人間に「実装を開始してよいか」と問うても、人間は計画全文を読まずに承認するだけで、判断の材料を持たないまま判断の手間だけが毎回発生していた。人間の判断を要する論点は承認推奨とは別に問いとして残るため、人間が決めるべきことを失わない。実装の誤りは工程7のレビューとマージ判断で人間が止められる。

## 却下した案

- 計画の実装開始は常に人間が承認する案（変更前の `skills/gh-maestro-orchestrator/stage-5-plan-review.md`）。人間が差し戻しを決めた修正版だけは問わずに進め、初回の計画と orchestrator が問わず差し戻した修正版では「この計画で実装を開始してよいか」を問う作りだった。最終承認を人間に置く方が安全に見えるが、承認推奨の計画では人間の判断が実質的に加わらず、待ち時間と応答の手間だけが残るため採らなかった。
