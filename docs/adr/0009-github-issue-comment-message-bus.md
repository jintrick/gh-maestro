# GitHub Issueコメントをメッセージバスとして使う

## 決めたこと

エージェント間の指示と報告の永続的な通信には、GitHub Issueコメントをメッセージバスとして使う。`msg-send.js`、`msg-poll.js`、`msg-read.js`を共通の配送窓口とし、コメントに残った状態を監視・再読できるようにする。

## なぜ

プロセスの標準入力やローカルキューだけに依存した通信は、ワーカーの終了や再起動をまたいで追跡しにくい。GitHub Issueコメントなら、指示と応答が永続化され、orchestrator と人間が同じ記録を確認できる。配送を共通窓口に集めることで、送信側ごとの実装差も抑えられる（Issue #45、PR #46・#55）。

## 却下した案

- プロセス間の一時キューだけを正本にする案。再起動後の再読と人間による確認ができないため採らなかった。
- ワーカーごとに標準入力やペインへ直接送る経路を正本にする案。配送状態が永続化されず、経路ごとの挙動差を生むため採らなかった。
- Issueコメントとローカル通信を送信者ごとに使い分ける案。どこに指示と応答があるかを一意にできないため採らなかった。
