# 役割と工程で検証できる完了シグナルを使う

## 決めたこと

完了通知は、送信者の役割と現在の工程に対応する応答契約として検証する。単に何らかの返信があったことや、すべての再開後に同じ返答を要求することを完了の根拠にしない。実装を完了した coder のように、PR作成自体が完了シグナルとなる工程では、不要な代理返信を求めない（Issue #194・#195）。

## なぜ

resume後の応答漏れを一律に代理送信すると、応答が必要な工程と、PR作成を完了として報告不要とする工程を区別できない。送信者の役割と工程を契約に含めれば、漏れを検知すべき場面だけを対象にし、正常な実装完了を誤って未完了扱いしない。

## 却下した案

- resumeを経たすべての処理に同じ応答を要求する案。工程ごとの完了方法を表現できず、正常なPR作成フローへ余分な応答を強制するため採らなかった。
- 返信が一つでもあれば完了とみなす案。役割や工程を検証できず、別の工程の返答を誤って完了として扱うため採らなかった。
- 応答漏れをすべて自動代理送信で隠す案。実際に完了したかという判断を機械的な返信の有無へ置き換えるため採らなかった。
