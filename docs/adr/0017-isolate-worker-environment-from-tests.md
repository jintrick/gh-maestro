# ワーカー環境をテストから分離し実リポジトリ操作を構造的に拒否する

## 決めたこと

ワーカーから引き継いだ環境変数をテストの実spawnへ漏らさない。テストの子プロセスは中立化した環境、一時ワークスペース、明示した作業ディレクトリを使い、実リポジトリや実Issueへ操作が届く経路を構造的に拒否する（Issue #202・#283・#284）。

## なぜ

ワーカー環境には実際のworkspaceやIssueを示す値が注入される。これを子プロセスが継承すると、テストが一時ディレクトリを指定していても実リポジトリを優先し、異常終了通知やGit操作を本番へ送る可能性がある。作業ディレクトリを指定するだけでは環境の優先順位を制御できないため、環境の中立化と実行経路の拒否を重ねる。

## 却下した案

- 各テストが自分でworkspaceだけを一時ディレクトリへ設定する案。継承された環境変数が優先される経路を塞げないため採らなかった。
- 実リポジトリへ届かないことをテスト担当者の注意だけに任せる案。新しい実spawnや環境差で再発し得るため採らなかった。
- ワーカー環境をそのまま子プロセスへ引き継ぎ、テスト後に影響を確認する案。本番のIssueやリポジトリを変更してからでは回復できないため採らなかった。
