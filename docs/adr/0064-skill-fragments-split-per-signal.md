# スキル断片は、合図ごとにその場で要るものだけを届くよう小分けにする

## 決めたこと

合図に応じて orchestrator のコンテクストへ自動で割り込ませるスキルのファイルを「スキル断片」と呼ぶ。スキル断片は、合図のたびに割り込むことを前提に小分けにし、各合図でその場で要るものだけが届くようにする。複数の工程で使う定義は共通の定義として1つのスキル断片に置き、工程ごとの内容は別のスキル断片に分ける。最初の適用として、前提を疑う問いのスキル断片を、共通の定義と工程1・工程5・工程7の各ファイルに分ける（#771）。

## なぜ

スキル断片は、通知のたびに orchestrator のコンテクストへ割り込む。1ファイルに複数の工程の節を持たせて丸ごと届けると、その場で要らない工程の節まで毎回割り込み、コンテクストを消費する。#771 では前提を疑う問いのスキル断片に工程7の節を足し、トリアージのスキル断片と一緒に届けた結果、レビュー完了の通知だけで 8,983 文字になり、Claude Code のフックが一度に渡せる 10,000 文字の手前に置いた上限 9,000 文字にほぼ達した。上限は超えてはならない天井であり、そこまで詰めてよい目安ではない。

## 却下した案

- 前提を疑う問いを、工程1・工程5・工程7の節を持つ1つのファイルにまとめて、各合図で丸ごと届ける案（#766 と #771 の初回の実装）。定義が1か所にまとまり読みやすく見えるが、トリアージや計画評価のたびに要らない工程の節が割り込むため採らない。定義を1か所にまとめる目的は、共通の定義を1つのスキル断片に置くことで守る。
- 上限 9,000 文字に収まるよう言い回しを圧縮して1ファイルのまま届ける案。収まっても要らない節は割り込み続け、工程を足すたびに既存の規範の文を削る圧力がかかるため採らない。
