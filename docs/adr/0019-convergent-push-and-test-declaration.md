# pushとテスト結果の申告を収束する最終操作にする

## 決めたこと

修正をpushするときは、対象のHEADと実行成果物に結び付いたテスト結果の申告までを、収束する最終操作として扱う。申告のcommit、成功・失敗件数、実行範囲などは自由記述から受け取らず、HEADと成果物から決定論的に導出して公開する（Issue #374・#417、PR #375・#418）。

## なぜ

修正pushの後にコーダーが申告を手入力する運用では、申告が省略されたり、別のcommitの結果が届いたりする。失敗件数や実行範囲が主張に依存すると、orchestratorはテストを機構で再実行しない方針のまま、対象commitに対応した事実を確認できない。pushと成果物から申告を収束させれば、再実行や手入力の往復を増やさず、結果の適用先を確認できる。

## 却下した案

- push後にテスト結果をコーダーが自由記述で追加する案。申告の漏れと対象commitの取り違えが起きるため採らなかった。
- 結果が古いときに機構がテストを再実行して補う案。環境差を持ち込み、停止と再実行を機構へ移すため採らなかった。
- commitや成果物と無関係な成功件数だけを申告する案。どの変更を検証した結果か確認できないため採らなかった。
