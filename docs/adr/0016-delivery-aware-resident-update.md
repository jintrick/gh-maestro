# 配送中の常駐プロセスを無条件に停止せず更新する

## 決めたこと

更新コマンドは、稼働中の常駐プロセスへ新しいコードを反映する際、配送中の状態を考慮した更新経路を使う。常駐プロセスを無条件に停止してから更新する手順を既定にしない（Issue #280・#281）。

## なぜ

常駐プロセスは起動時のコードを保持するため、ファイルを更新しただけでは実際の配送処理が新しくならない。一方、無条件に停止してから起動すると、更新中に指示の配送や監視が途切れ、再開に必要な状態を失う可能性がある。更新を配送のライフサイクルへ組み込むことで、修正を反映しながら常駐サービスの責務を保つ。

## 却下した案

- ファイルを置き換えるだけで更新完了とみなす案。稼働中プロセスは古いコードを保持するため、実際の動作へ反映されないため採らなかった。
- 毎回プロセスを無条件に停止し、更新後に起動し直す案。配送を中断し、状態や指示を失う経路を作るため採らなかった。
- 修正の反映を人間が手作業で停止するまで待つ案。更新コマンドの責務から常駐プロセスの切り替えを外し、古い動作を長時間残すため採らなかった。
