# 管理領域と実行時状態を物理的に分離する

## 決めたこと

インストーラーが管理する `~/.gh-maestro/` と、インストールで削除されてはならない実行時状態を物理的に分ける。PIDレジストリやロックは `scripts/shared/storage-layout.js` の `runtimeRoot()` または `workspaceRuntimeDir()` に置く。`workspace` は `scripts/shared/workspace.js` の `resolveWorkspace()` から取得し、ホームや管理領域との衝突は fail-closed で拒否する。管理領域の新しい最上位項目は `MANAGED_TOP_LEVEL` に先に宣言する。

## なぜ

`install.js` は管理領域に自分が管理していない最上位項目があれば削除する。workspace の解決を誤ると、workspace 内に置いた実行時状態が管理領域と同じ場所になり、インストールによって稼働中プロセスのPIDレジストリやロックが消える。これは文字列の検索では検出できず、実行時の `workspace` の値を検証しなければ分からない。管理領域と実行時状態を物理的に分け、解決時に衝突を閉じた状態で拒否することで、削除と二重起動防止の事故を防ぐ。

## 却下した案

- PIDレジストリやロックを `<workspace>/.gh-maestro/` に置き続ける案。workspace が誤解決したときにインストーラーの削除対象と衝突するため採らなかった。
- `.gh-maestro` という文字列を検索する静的検査だけで安全性を確認する案。正しい利用箇所も多数あり、実際の workspace の値の誤りを検出できないため採らなかった。
- 呼び出し箇所ごとに独自の workspace 解決処理を作る案。検証漏れによる経路ごとの挙動差を生むため採らなかった。
