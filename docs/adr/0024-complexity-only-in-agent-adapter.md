# 複雑さを許すのはエージェントアダプター層だけ

## 決めたこと

複雑な設計案が浮かんだらまず疑い、既存の仕組みの流用や不要コードの削除で済まないかを先に検討する。複雑さが正当化されるのは、AI エージェント CLI 間の差異を吸収するアダプター層だけとする。オーケストレーション本体には持ち込まない。

## なぜ

エージェント CLI ごとに起動方法・引数・出力形式・サンドボックスの挙動が異なり、その差異は消せない。ここだけは複雑にならざるを得ない。一方、オーケストレーション本体は工程と判断の流れであり、複雑にすると人間が追えなくなる。追えない箇所は検証されないまま残る。

複雑さの置き場所を1箇所に決めておかないと、差異吸収のための複雑さが本体へ滲み出し、どこまでが本質でどこからが都合かの区別がつかなくなる。

## 却下した案

- 層を分けず、必要な場所に必要なだけ複雑さを許す案。滲み出しを止める根拠がなくなるため採らなかった。
- アダプター層も単純に保つ案。CLI 間の差異が実在する以上、単純にすればどこかで対応が抜ける。
