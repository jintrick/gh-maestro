# 監視と配送を常駐する外部プロセスに分離する

## 決めたこと

GitHub上の新着指示の監視とエージェントへの配送は、エージェントの外側で動く常駐プロセスが担う。エージェント自身に定期監視を依頼せず、常駐プロセスが新着時だけ対象へ伝える（Issue #134、PR #139）。

## なぜ

エージェント自身に監視をさせると、作業の実行と監視の責務が混ざり、作業中や終了間際の配送状態を一貫して扱えない。外部プロセスならエージェントが作業をしていない間も監視を継続でき、通信の失敗や再開をエージェントの判断から切り離せる。

## 却下した案

- 各エージェントが自分でIssueを定期的に確認する案。監視の重複と確認漏れが生じ、作業状態によって配送が止まるため採らなかった。
- エージェントの実行プロセス内に監視ループを組み込む案。作業の再試行や終了と監視のライフサイクルが結合するため採らなかった。
