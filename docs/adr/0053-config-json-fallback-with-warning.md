# config.json が壊れていたら、書き換えずに既定値で動き、必ず警告する

## 決めたこと

`config.json`（gh-maestro の設定ファイル）が読めないとき、または中身の一部が壊れているときは、既定値で動いてよい。ただし、どのファイルのどこが壊れていて、代わりに既定値を使ったことを、必ず警告として示す。黙って既定値に切り替えてはならない。

壊れた `config.json` を、gh-maestro が自分で書き換えて直してはならない。既定値で動くのは読み込んだ値の上だけで、ファイルはそのまま残す。直すのは人間である。

`config.json` は、AGENTS.md「状態ファイルの読み取り」と ADR 0036 が「壊れていたら止める」とする管理用の状態ファイルには当たらない。人間が編集する設定であり、壊れていても既定値で動き続ける方が害が小さい。

## なぜ

Issue #682 のテストの見直しで、`config.json` が壊れていると黙って既定値で動く作りと、壊れた設定の一部を黙って直す作りが見つかった。テストは、どちらの動きも仕様として固定していた。ADR 0036 に照らすと止めるべきに見えるため、規範違反の疑いとして挙がった。

設定ファイルは人間が手で書き換えるもので、書き間違いが起きる。そのたびに gh-maestro 全体が止まると、作業が進まなくなる。一方で、黙って既定値に切り替わると、人間は自分の設定が効いていないことに気付けない。設定したはずのエージェントやモデルとは別のもので、作業が進んでしまう。既定値で動きつつ警告すれば、どちらの害も避けられる。

ファイルを書き換えて直す作りは、さらに危険である。人間が書いた設定が、気付かないうちに消えたり、別の値に変わったりする。壊れた原因（書きかけ、別の作業との競合など）も分からなくなる。

## 却下した案

- ADR 0036 と同じく、壊れていたら止める（Issue #682 で、規範違反の疑いとして挙がった）。設定の書き間違いのたびに全体が止まる代償が大きいため、採らなかった。
- いまのまま、黙って既定値で動く。人間が設定の不発に気付けないため、採らなかった。
- 壊れた設定を、gh-maestro が書き換えて直す（いまの作りに含まれていると、Issue #682 の判定で分かった）。人間の設定が気付かないうちに失われるため、採らなかった。
