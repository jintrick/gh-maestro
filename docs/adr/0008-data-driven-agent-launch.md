# エージェント設定と起動をデータ駆動にする

## 決めたこと

エージェントの設定、既定値、プロファイル、スキルとエージェントの割り当ては、共有の設定と起動ヘルパーで管理する。役割を追加・変更するときは `skills/agents.yaml` などのデータを優先して更新し、エージェントごとの条件分岐や重複した起動処理を増やさない。

## なぜ

役割ごとに起動処理を複製すると、引数、プロンプト配送、ライフサイクルの修正が一部のエージェントにしか届かず、設定と実際の動作がずれる。設定をデータとして集約し、起動経路を共有すれば、役割の追加が既存の検証・配布・運用規則から外れず、変更箇所もレビューできる（Issue #41、PR #42）。

## 却下した案

- 新しい役割ごとにスクリプトの条件分岐と専用起動経路を追加する案。重複と役割間の動作差を増やすため採らなかった。
- エージェントの既定値を起動スクリプトへ直接埋め込む案。設定変更と実装変更が分離できず、全経路の整合性を確認しにくくなるため採らなかった。
