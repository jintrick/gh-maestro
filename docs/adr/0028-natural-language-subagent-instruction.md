# サブエージェントの利用は自然言語の指示に留め、CLI固有の設定を持たない

## 決めたこと

スキル文書がサブエージェントの利用を指示するときは、目的を自然言語で書くに留める。ツール名、引数、モデル名、設定ファイルなど、エージェントCLI固有の記述をスキル文書やリポジトリに持たない。指示が通じないCLIは、その役割に割り当てない（Issue #443）。

## なぜ

エージェントCLIは速い周期で変わる。ツールの引数もモデル名も設定ファイルの置き場所も、こちらの都合とは無関係に更新される。それらをスキル文書やリポジトリの設定として抱えると、CLIが変わるたびに追随が必要になり、追随しそこねた記述は静かに嘘になる。役割の割り当てを変えるだけで済ませられるなら、そちらの方が保守の総量が小さい。

サブエージェントの実行モデルを安いものへ固定できれば探索のコストは下がるが、その指定手段はCLIごとに異なり、いずれも固有の設定を抱え込むことになる。コストの最適化より、記述が古びないことを優先する。

## 却下した案

- リポジトリに `.codex/agents/explorer.toml` を置き、ビルトインのサブエージェントを安いモデルで上書きする案。プロジェクトスコープの設定として実現可能で、worktree にも自動的に入ることを確認した上で採らなかった。codex 固有の設定形式に依存し、ファイル配置・キー名・モデル名のいずれかが変わるたびに追随が必要になるため。
- スキル文書にCLIごとの分岐（codex はこう、Claude Code はこう、agy はこう）を書く案。エージェントが増減するたびに全スキルの改訂が必要になるため採らなかった。
- サブエージェントの利用そのものを禁じたままにする案。事実を持たないまま設計が返る問題（Issue #440）が解決しないため採らなかった。
