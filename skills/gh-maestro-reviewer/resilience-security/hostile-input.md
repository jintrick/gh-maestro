# Resilience & Security / Hostile Input

目的: この変更を壊す・悪用する方法を探る。悪意ある入力や権限昇格の経路を評価する。

## 確認順序

1. 攻撃可能性を確認する。
2. 入力・設定・引数を通じて安全機構を無効化できないか確認する。
3. 認可境界と他ユーザーデータへの影響を確認する。

## 重点

- スタックトレースやsecretの露出
- SQL/Shell/HTML injection、path traversal
- 認証バイパス、認可漏れ、認可境界、他ユーザーデータへの影響
- 危険なデシリアライゼーション、`eval`, `new Function`
- リソース枯渇攻撃(DoS)
- 設定・引数経由での安全機構の無効化

## 外部参照の裏取り

diffが参照する認証・認可ヘルパー、入力検証ロジックは、
判定前に実ファイルを読んで確認する。挙動を推測しない。

## 禁止

- **スコープ限定なしの全件テスト実行（`npm test` 等）および全体ビルド（`npm run build` 等）は禁止。** diffで変更された特定のテストファイルのみを対象にしたピンポイント実行（例: `node --test tests/<file>.test.js`）は許容する
- UX議論
- 純粋な保守性議論
- テスト実行の要求
- severity判定根拠を明示できない推測指摘
