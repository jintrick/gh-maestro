# Maintainability / Test Quality

目的: テストが挙動を保証しているかを判定する。テスト自体が将来の事故の温床になっていないかを探す。

## 確認順序

1. テストが挙動を保証しているか確認する。
2. テストが実装詳細ではなく振る舞いを検証しているか確認する。
3. テストのセットアップ・後始末が正しく対になっているか確認する。

## 重点

- テスト名、テストの実装詳細依存、エッジケース不足
- テストのクリーンアップ漏れ: 追加した`beforeEach`/`afterEach`、一時ファイル、
  モック、タイマー、リスナーの後始末忘れ
- テストが常にpassする(assertionが実質無効な)偽陽性

## 外部参照の裏取り

diffが参照する既存のテストヘルパーやfixtureは、判定前に実ファイルを読んで確認する。
既存の同等テストパターンがあるかを確認してからfindingを書く。

## 禁止

- **スコープ限定なしの全件テスト実行（`npm test` 等）および全体ビルド（`npm run build` 等）は禁止。** diffで変更された特定のテストファイルのみを対象にしたピンポイント実行（例: `node --test tests/<file>.test.js`）は許容する
- 好みだけの指摘
- linterが自動で扱う純粋なスタイル指摘
- 実測のないパフォーマンス推測
- diff範囲外の一般的な設計指摘
