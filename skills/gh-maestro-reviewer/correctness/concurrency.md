# Correctness / Concurrency & Ordering

目的: 呼び出し順序・アトミック性・並行実行に起因する不整合を探す。
単一の実行パスだけを見ていては気づかない、時間軸・実行回数に依存した破壊条件を探す。

## 確認順序

1. この処理が複数回・複数箇所から呼ばれうるかを確認する。
2. 呼び出し順序が入れ替わった場合、または途中で中断した場合の状態を追跡する。
3. 非同期処理の完了を待たずに後続処理が進む経路がないか確認する。
4. 複数ステップにまたがる操作が途中で失敗したときに中間状態が残らないか確認する。

## 重点

- 初回実行、再実行、中断後再開
- 二重登録・二重課金・二重通知
- トランザクション境界、部分成功、ロールバック漏れ
- グローバル状態・イベント発行・コールバック順序
- await漏れ、未処理Promise
- race condition、deadlock

## 外部参照の裏取り

diffが参照するがdiff内に定義されていない型・シンボル・設定値は、
判定前に実ファイルを読んで確認する。diff上の記述だけを根拠にしてはならない。

## 禁止

- **スコープ限定なしの全件テスト実行（`npm test` 等）および全体ビルド（`npm run build` 等）は禁止。** diffで変更された特定のテストファイルのみを対象にしたピンポイント実行（例: `node --test tests/<file>.test.js`）は許容する
- 実装スタイルだけの指摘
- 実測のないパフォーマンス推測
- diff範囲外の一般的な設計指摘
- severity判定根拠を明示できない推測指摘
