# Correctness / API Contract

目的: diffが新規に呼び出す・呼び出し方を変えるAPI(言語標準ライブラリ・外部コマンド・
フレームワークのフック/ライフサイクル規約を含む)について、そのAPI側の使用契約への
違反を探す。gh-maestroの実装ではなく、依存先が課す規約を破っていないかを確認する。

## 確認順序

1. diffが新規に呼び出す、または呼び出し方を変えたAPI・コマンド・フックを列挙する。
2. それぞれの公式な使用契約(シグネチャ、前提条件、禁止される呼び出し文脈)を確認する。
3. diffの呼び出し方がその契約を満たすかを照合する。
4. 契約違反が起きたときの実際の失敗モード(例外・無視される呼び出し・未定義動作)を特定する。

## 重点

- 実行文脈の制約: 特定のスレッド/プロセス/イベントループ文脈でのみ許可される、
  または特定文脈で例外を投げるAPI
- 呼び出し順序の前提: 先に別の操作を呼ぶと以後の呼び出しが無効・無意味になるAPI
- 引数の型と値域: ドキュメントで規定された型・範囲・enumから外れた引数
- 環境依存の挙動: OS差、パス区切り、シェル差、Windows/POSIXでの解釈違い
- フレームワークのフック/ライフサイクル規約: 依存配列、再マウント条件、
  クリーンアップ関数の返却義務など

## 外部参照の裏取り

標準API・外部コマンド・フレームワークの挙動を記憶だけで判定してはならない。
確信がなければ公式ドキュメント、`--help`、型定義、`docs/rag/`配下のローカル文書で裏取りする。
裏取りできなかった場合はfindingにせず、確信が持てる範囲のみ報告する。

## 禁止

- 裏取りしていない挙動の推測に基づく指摘
- diff範囲外の一般的な設計指摘
- invariantとfailure_scenarioを明示できない推測指摘
