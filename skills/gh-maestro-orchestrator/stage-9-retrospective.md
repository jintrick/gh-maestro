# 工程 9. 反省会と後始末【必須】

このファイルは、同じIssueを担当するorchestratorが工程9で実行する手順の正本である。工程番号・必須／任意・入口／待機／遷移を確認して進める。人間への発言と工程横断の不変条件はSKILL.mdに従う。

入口: stage-8の確認後。待つもの: 反省会の実施または人間が承認したスキップ、および決定事項本文。次: finalize完了で終了。

## 9-[1/3] 分析対象【必須】

レビューでcoderへ転送したBLOCKER・命名修正、保留Issueに積んだSUGGESTION、発動したスパイラル検知を集める。実装者本人を反省会に参加させる。反省会が完了するまでワーカーを削除しない。

## 9-[2/3] 実施判断【必須】

分析対象が1件以上なら実施し、`retrospective.md` に従う。0件の場合だけ、`工程9-[2/3]` と名乗り、レビュー指摘が0件であることを判断材料として反省会を実施するかスキップするか尋ねる。回答があるまで待つ。「実施する」なら反省会へ進み、「スキップする」なら完了扱いにする。素案の提案が0件でも素案を提示し、人間の返答があるまで次へ進まない。

## 9-[3/3] 決定記録と後始末【必須】

人間の判断と承認済み対応を反映した決定事項本文を `/tmp/retro-decision-<N>.md` に書く。スキップ時も、理由（例: `レビュー指摘0件のため反省会をスキップ`）、判断、反映先なしを記録する。`finalize-issue.js` はこのコメントを先にIssueへ投稿してから後始末するため、別途同じ決定コメントを投稿しない。

```sh
node "{{SCRIPTS_PATH}}/write-draft.js" /tmp/retro-decision-<N>.md --stdin <<'EOF'
<決定事項>
EOF
node "{{SCRIPTS_PATH}}/finalize-issue.js" --issue <N> --repo $REPO --workspace $WORKSPACE --decision-file /tmp/retro-decision-<N>.md
```

決定事項の投稿に失敗した場合は後始末されない。エラーを確認して対応し、人間の判断や承認済み作業が未完了ならfinalizeを行わない。

この手順書は工程9で実行する内容の正本である。人間への発言はSKILL.md「人間への発言の規範」に従う。
