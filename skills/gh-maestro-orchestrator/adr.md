# ADRの書き方（参照専用）

いつ書くか、ADRにする3条件、「却下した案」を作文しない旨、遵守の限界、3条件を満たさない判断の行き先は `SKILL.md` 側にある。このファイルは**3条件を満たすと判定した後**の書式・採番・改訂の扱いだけを持つ。判定より前に開く必要はない。

## 書式と採番

置き場所は `docs/adr/`、ファイル名は `<NNNN>-<英小文字とハイフンのスラッグ>.md`。

- `<NNNN>` は既存ファイルの最大番号 + 1（4桁ゼロ埋め）。欠番は埋めない。削除した番号も再利用しない。
- 本文の見出しは `## 決めたこと` `## なぜ` `## 却下した案` の3つだけを使う。増やさない。
- 本文からIssue番号・PR番号を参照してよい。実装手順やコードの引用は書かない（コードを読めば分かることはコードに残す）。
- 書いた判断は、規範として記録する場所（`AGENTS.md` の該当行、`.claude/rules/` のファイル、または `skills/**/SKILL.md`）に `理由と経緯: docs/adr/…` を添える。判断がワーカーの実装や振る舞いを直接縛らない場合も、適切な場所が無ければ `AGENTS.md` に参照行を置く。

3条件を満たすと判定した後の作成は、`{{SCRIPTS_PATH}}/create-adr.js` を唯一の入口にする。先に `--next --slug <slug> --workspace <path>` で割り当てられる相対パスを取得し、そのパスで規範文書の参照行や、既存ADRを覆す場合の旧ADR・参照元を更新する。その後、次の形式で作成経路を実行する。

```sh
node "{{SCRIPTS_PATH}}/create-adr.js" \
  --slug <slug> --body-file <path> \
  --normative-file <path> \
  [--supersedes docs/adr/<旧ADR>.md] --workspace <path>
```

スクリプトは番号を現在の `docs/adr/` から再計算し、参照行の対象が一致しない場合はADRを作成しない。作成したADRのfront matterには、指定した規範ファイルのリポジトリ相対パスを記録する。

規範ファイルは、呼び出し側が `--next` の出力を参照行へ書いた後に指定する。コードフェンス内の例は参照行として扱われない。front matterを持つ既存ADRは、記録された規範ファイルとそのADRへの参照行が実在することを検査する。front matterの無い既存ADRは、既存資産としてこの検査の対象外とする。

```markdown
# <決めたことを一文で言い切ったタイトル>

## 決めたこと

<何を決めたか。実装の説明ではなく、決定そのものを書く>

## なぜ

<その判断に至った理由。何が問題で、この選択によって何が起きなくなるのか>

## 却下した案

<実際に検討して採らなかった案と、採らなかった理由>
```

## 既存のADRを覆したとき

- 旧ADRのファイルと番号は残す。他の文書からパスで参照されているため、番号を再利用しない。
- 新しい判断は新しい番号で書き、旧ADRのタイトル直下に「この判断は `docs/adr/…` で覆された」の1行を追記する。
- 旧ADRを指していた参照（`AGENTS.md` 等）を新しいADRへ張り替える。
- **3条件を満たしていなかったと後から分かったADRは、覆されたのではなく最初から成立していない。** その場合はファイルごと削除し、参照元からも消す（実例: コミット `ca14c77`）。
