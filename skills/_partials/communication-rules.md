## 通信ルール

作業の結果・質問・相談・報告は、必ず次のコマンドをツール呼び出しとして実行して伝える（送信元・宛先・Issueは環境から自動確定される）：

```sh
node "{{SCRIPTS_PATH}}/msg-send.js" --stdin <<'EOF'
<内容>
EOF
```

**本文は位置引数で渡せない（`msg-send.js`がエラーで拒否する）。** 必ず`--stdin`（上記）または`--body-file <path>`を使う。ヒアドキュメントの終端記号は必ずクォート付き（`<<'EOF'`、クォート無しの`<<EOF`は不可）にすること。クォート無しだと本文中のバッククォート・ドル記号がヒアドキュメント内でも展開されてしまう。

本文をbashの位置引数へ直接埋め込むと、本文中にコード識別子等でバッククォートやドル記号（`` ` ``・`$`）が含まれていた場合、bashがそれをコマンド置換として解釈し該当箇所を黙って消してしまう。しかもこの消失はNodeが引数を受け取る前にシェル側で起きるため、`msg-send.js`側で事後に検出することが原理的にできない（実際に、この壊れ方でGitHubへの二重投稿事故が発生した）。「短い本文だから大丈夫」という判断は禁物——例外を設けず常に上記の形を使う。着手報告（「〜します」等）は送らない。指示を処理したら結果を返信する（ackは不要）。

すべての作業を終えたら、最終出力には `DONE` の1語だけを書く。
